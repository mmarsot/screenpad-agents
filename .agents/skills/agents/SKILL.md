# Agent app

Owning files: `screenpad_agents/` (`common`, `config`, `herdr`, `keymap`, `screen`, `firstmate`, `card`, `fleet`, `app`, `cli`, imported in that order, one way) and `agents.py`, the launcher that puts its own directory and `vendor/` on `sys.path` and runs its `cli.main()`. Installed in `~/.local/lib/screenpad-agents/`, with `~/.local/bin/screenpad-agents` a link and `systemd/screenpad-agents.service` its user unit (see the [install](../install/SKILL.md) skill).

Read first:

- [docs/agents.md](../../../docs/agents.md): what it shows, the card and how it answers safely, the keymap, the config, how it reads and acts on Herdr and firstmate.
- [screenpad-linux's docs/app-api.md](https://github.com/mmarsot/screenpad-linux/blob/main/docs/app-api.md): the socket protocol it speaks, its limits, the touch rules (arming, cancels) it relies on, and the client library.

## Rules

- **An app like any other.** It talks to the touch bar only through the socket, with the client library `screenpad_app` (its `Link`, the socket's path, the limits and `clip`), and **imports nothing of the daemon, `screenpad_touchbar`** (`test_imports_nothing_of_the_daemon`), which lives in screenpad-linux. A protocol or library change is made in screenpad-linux first; this app then moves its pinned commit (the [contributing](../contributing/SKILL.md) skill) and follows. Standard library plus `screenpad_app` only, shebang `python3 -I`.
- **Off until configured.** Without `agents.toml` (or `--config`) every command exits 2 before touching anything; install never enables the unit, and the unit has `ConditionPathExists`. Nothing defaults to a firstmate home or checkout: without `[firstmate]` nothing of firstmate is read. The config is strict (unknown keys and bad values are `ConfigError`); a new setting needs parsing, its error, docs/agents.md and tests.
- **Herdr is the authority** on which agents run and their state; the app shows `agent list` as it is, in Herdr's order, and never infers state. **Every Herdr call passes `--session <configured session>`**; none relies on the ambient session.
- **firstmate through its own commands only**: the reader `FM_HOME=<home> <code>/bin/fm-bearings-snapshot.sh --json --fields endpoints`, at most every `[firstmate] poll` (60 s or more) plus on demand when Captain's Call is tapped, and `FM_HOME=<home> <code>/bin/fm-control.sh <task id> interrupt` on Interrupt for a task, and `fm-inbox.sh note` for the board (`firstmate.py`), each with no other `FM_*` variable passed on. Never parse firstmate's files. The count is `len(decisions_open) + len(contributions.captain)`; the join is the endpoint target `<session>:<pane id>`, and `fm-bearings-board.sh path` finds the board (below).
- **A Captain's Call tap opens the decisions board, and answers nothing**: its file is `FM_HOME=<home> <code>/bin/fm-bearings-board.sh path` (only `path`, never `build`: firstmate composes and arms the board), it is open when `[firstmate] lavish` (bare `lavish-axi`, its session listing) lists that file `open` (both paths resolved), and only a loopback `http` URL goes to `gio open`. With none open the app asks a question in the bar whose **Open decisions board** asks firstmate to build it: one `FM_HOME=<home> <code>/bin/fm-inbox.sh note --json --request-id <id> -- <BOARD_REQUEST>` (one wake), then none again until a tap finds the board open or `BOARD_REQUEST_HOLD` passes; the id is made per request and kept after a failed note (fm-inbox.sh may have saved it, exit 1 or 3), so a retry replays rather than queueing a second, and a new one is made once the id is older than the hold (firstmate may have handled that note, and a replay wakes nothing) or once the board was seen open; a replay whose `fm-inbox-note.v1` answer is `acknowledged` or whose `path` is in firstmate's handled inbox (it wakes nothing) is asked again at once, in the same job, under a new id (no extra reads or timers meanwhile; Lavish opens the built board itself). That note is the only thing it writes into firstmate; it never calls `fm-captain-hold`, and answering on the panel is not agreed. Tests use a stand-in opener and a stand-in `fm-inbox.sh` in the fake checkout, so nothing opens on the screen and no firstmate home is written.
- **Keys reach an agent only two ways**: an answer through `screen.guarded_send`, or Interrupt. An answer is sent only if, at the moment of sending, Herdr reports the pane still blocked by the same kind of agent, with the `state_change_seq` recorded at draw, and a fresh `pane read` taken right before `send-keys` has the digest of the lines drawn (`screen.mismatch`); otherwise nothing is sent and the card is drawn again. Never guard on Herdr's pane `revision` (it does not move when a dialog changes). Interrupt through Herdr keys checks the same kind of agent is in the pane; for a firstmate task it is `fm-control.sh` only.
- **A tap names the screen it was made on**: the answer buttons' ids carry `Screen.token()` (the seq and the lines' digest), so a changed screen is new widgets the touch bar re-arms for 0.3 s; `Card.answer_for` takes only a token equal to the screen held now, and hides the buttons while an answer is pending. Keep Back, Focus and Interrupt ids stable (a widget whose id changes on every read never arms).
- **The keymap answers only what it recognises** (`keymap.py`): a harness entry offers an answer only when the drawn lines show its option, never Always without the plain yes, and never a dialog its `refuse` pattern matches (Claude Code's folder-trust, external-imports and bypass dialogs, which must never get a key). An unknown kind is read-only. A new harness or key needs a lab check of its dialog and tests in `test_agents_card.py`.
- **Slow calls stay off the loop**: Herdr, firstmate's reader and firstmate's control (interrupts, opening the board and asking for one) each run in their own thread (`app.py`) and hand results through a queue and a wake pipe, so a touch is handled at once. A worker never dies on an error: any exception from a read is shown and logged like the source's own errors, and one from a focus is logged, one from an answer or an interrupt is shown on the card (`test_an_unexpected_error_keeps_both_threads_going`, `test_a_refused_focus_is_logged_and_the_loop_goes_on`, `test_a_failed_send_is_shown_and_the_card_stays`). A widget's id is derived from its pane (`fleet.widget_id`), and `Fleet.pane_of` answers only for the page last built, so a tap means the agent that was drawn.
- Keep widget text free of anything that changes on every read (times, counters): a widget that changes re-arms for 0.3 s and cancels a finger on it.

## Tests

- `tests/bar_support.py`, the stand-in touch bar: `Apps` and `AppServer` shaped like screenpad-linux's daemon (`pages`, `provided()`, `press`, `event`, `asks`), checking every message against app protocol 2 with the limits written out from docs/app-api.md, not imported from the library. Keep it to the protocol as documented: when the protocol changes, change it with the pinned commit. It draws and arms nothing; the touch rules are tested in screenpad-linux.
- `tests/agents_support.py` (the checkout and `vendor/` on `sys.path`, a fake `herdr` script, a fake firstmate checkout whose reader prints an `fm-bearings.v1` model and whose `fm-control.sh`, `fm-bearings-board.sh` and `fm-inbox.sh` record their calls, `fake_lavish` and `fake_opener`, `dialog()` a Claude Code permission dialog, `FakeHerdr` with screens and an `after_read` hook, `FakeFirstmate`, `config()`, `Rig`), then one file per area: `test_agents_config.py` (the config, the opt-in, the clients `cli.clients` builds from it, `show`), `test_agents_sources.py` (the Herdr client, firstmate's reader and interrupt), `test_agents_fleet.py` (the page and tiles through the stand-in's validation), `test_agents_card.py` (screen lines, the keymap, the card's widgets, the guard), `test_agents_app.py` (the loop against the stand-in's `AppServer`, the import rule, `run` and SIGTERM), `test_agents_answers.py` (the card in the loop: answers, a dialog changing between draw and tap, interrupts), `test_agents_board.py` (finding, opening and requesting the decisions board, and the tap and the card in the loop).
- **Never run against a live Herdr session or a real firstmate home**: tests use the fakes. A manual check uses an isolated Herdr session with fake agents (a script named `claude`, run by absolute path, printing a permission dialog) and a throwaway firstmate home with a task record whose endpoint is the lab pane; the app's Herdr command there is a wrapper that checks the trailing `--session` is the lab session and runs the call through the lab helper.
- [docs/development.md](../../../docs/development.md#tests) lists what these tests cover; keep it in step.
