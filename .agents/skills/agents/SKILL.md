# Agent app

Owning files: `screenpad_agents/` (`common`, `config`, `herdr`, `keymap`, `screen`, `desktop`, `firstmate`, `nomistakes`, `ssh`, `card`, `reviewcall`, `callpage`, `boardrequest`, `reviewrequest`, `fleet`, `runcard`, `runmodel`, `runlist`, `runs`, `runscan`, `remotewatch`, `runwatch`, `projectmodel`, `projectpage`, `projectwatch`, `usage`, `usagepage`, `usagewatch`, `extras`, `herdrwork`, `app`, `cli`, imported in that order, one way) `icons/` (its SVGs), and `agents.py`, the launcher that puts its own directory and `vendor/` on `sys.path` and runs its `cli.main()`. Installed in `~/.local/lib/screenpad-agents/`, with `~/.local/bin/screenpad-agents` a link and `systemd/screenpad-agents.service` its user unit (see the [install](../install/SKILL.md) skill).

Read first:

- [docs/agents.md](../../../docs/agents.md): what it shows, the card and how it answers safely, the keymap, the config, how it reads and acts on Herdr and firstmate.
- [docs/runs.md](../../../docs/runs.md): the Runs page: which projects, the joins, the warning rule, a run's card, the commands it runs and how often.
- [docs/projects.md](../../../docs/projects.md): the Projects page, its settings and the settings file's schema; [docs/usage.md](../../../docs/usage.md): the usage tile.
- [screenpad-linux's docs/app-api.md](https://github.com/mmarsot/screenpad-linux/blob/main/docs/app-api.md): the socket protocol it speaks, its limits, the touch rules (arming, cancels) it relies on, and the client library.

## Rules

- **An app like any other.** It talks to the touch bar only through the socket, with the client library `screenpad_app` (its `Link`, the socket's path, the limits and `clip`), and **imports nothing of the daemon, `screenpad_touchbar`** (`test_imports_nothing_of_the_daemon`), which lives in screenpad-linux. A protocol or library change is made in screenpad-linux first; this app then moves its pinned commit (the [contributing](../contributing/SKILL.md) skill) and follows. Standard library plus `screenpad_app` only, shebang `python3 -I`.
- **Off until configured.** Without `agents.toml` (or `--config`) every command exits 2 before touching anything; install never enables the unit, and the unit has `ConditionPathExists`. Nothing defaults to a firstmate home or checkout: without `[firstmate]` nothing of firstmate is read. The config is strict (unknown keys and bad values are `ConfigError`); a new setting needs parsing, its error, docs/agents.md and tests. A command setting is a string, split into words by `shlex.split` (no shell runs it; an unparsable or empty one is a `ConfigError`), or a list of words used as is (`config._command`).
- **Herdr is the authority** on which agents run and their state; the app shows `agent list` as it is, in Herdr's order, and never infers state. **Every Herdr call passes `--session <configured session>`**; none relies on the ambient session.
- **firstmate through its own commands only**: the reader `FM_HOME=<home> <code>/bin/fm-bearings-snapshot.sh --json --fields endpoints` (`endpoints,paths` with `[runs] firstmate`), at most every `[firstmate] poll` (60 s or more) plus on demand when Captain's Call is tapped, and `FM_HOME=<home> <code>/bin/fm-control.sh <task id> interrupt` on Interrupt for a task, and `fm-inbox.sh note` for the board (`firstmate.py`), each with no other `FM_*` variable passed on. Never parse firstmate's files, with one exception: the Projects page's two (below). The count is `len(decisions_open) + len(contributions.captain)`; the join is the endpoint target `<session>:<pane id>`, and `fm-bearings-board.sh path` finds the board (below).
- **The Projects page shows settings firstmate owns, and writes none of them** (`projectmodel.py`, `projectpage.py`, `projectwatch.py`; [docs/projects.md](../../../docs/projects.md) has the schema, which is part of the contract: change both together). It reads `<home>/data/projects.md` (a line `- <name> [<tags>] - <about>`: `[no-mistakes]`, `[direct-PR]`, `[local-only]` and `+yolo`; unknown tags and lines, archived projects skipped) and `<home>/data/project-settings.toml` (`[projects.<name>]`: `preset`, `annotated_review`, `where`, `model`, `effort`; every key optional, absent means the default, wrong values ignored) as text, read-only, in its own thread every `PROJECTS_POLL` s (`PENDING_POLL` while a change is pending) and **never while the touch bar is disconnected** (`ProjectsWatch.showing`). The app **never writes either file nor anything else in firstmate's home**: a tap only **stages** a change in the draft (`Projects.draft`, in memory) and **sends nothing**; **Validate** gives every drafted change of every project (`Projects.validate`) to one `Firstmate.note` (`fm-inbox.sh note --json --request-id <unique id> -- 'ScreenPad Projects page: set <project> <what> to <value>; set …'`, `projectmodel.note_text`, only registry names and a fixed vocabulary in it), shows them pending (`Projects.pending`) until a read `reflects` them or `PENDING_HOLD` passes, and a failed note makes them the draft again with the error; Discard drops the draft. A preset shows lit only while its bundle holds (`Project.effective_preset`); the app never infers one. Widget ids name what a tap does and `Projects._actions` is rebuilt on every change, so a tap on an id no longer drawn does nothing (`test_projects_page.py`). The page is the app's 4th page, the protocol's limit (`MAX_PAGES`). The list is a grid of project cells (three to a row, nine to a page, `PER_PAGE`): **a tap on a cell opens its settings**, and the list has no preset or Settings buttons (the presets are on the project's view); Previous and Next page it.
- **Bearings is the one-tap board** (`BoardRequest.rebuild`, `Fleet.bearings_tile`, the `bearings` tile): the board is opened straight away when it is open and `Firstmate.board_age` (its file's mtime, never its contents) is at most `BOARD_FRESH`; otherwise one note `REBUILD_REQUEST` asks firstmate to rebuild it and the control thread's check opens it (`open_board`) as soon as it is open **and its file is newer than the request** (`_rebuilt`; a stale open board ends no wait). It shares the board's state and wait with Captain's Call, whose page and `calls` tile behave as before. On the bar a tile with an icon shows only it: the compass shows while idle, its words while asking or failed.
- **The Limits page and the usage tile run quota-axi, at most once a minute, only while connected** (`usage.py`, `usagepage.py`, `usagewatch.py`, `[usage]`, off without it): `quota-axi --json` (schemaVersion 5: `providers[].windows[]` with `percentRemaining`, `resetsAt`, `pace.status`; `state.error` when unreadable) is read by `usage.parse`; **`[usage] providers`** (default: every provider quota-axi can read, a provider it says nobody set up left out) is applied in `parse(text, only)`, so a hidden provider is in no page row, tile word or badge (`Usage.left`); a provider with no windows is "No data" with its reason in words and **never a number**. The page (`usagepage.page`, `[usage]`'s `page = "limits"` item: **a tile cannot turn the apps page**) is a grid six columns wide, a block of rows per provider (logo across its rows, then per window its plain name and reset in words, a bar as a `lines` widget of block characters, the percent), the Details row last, at most `MAX_ROWS`; only Details (`limits.details`) takes a touch. The tile is a gauge icon with the tightest percent as its badge (words, no icon, when nothing was read, since a tile with an icon shows only it). **Details** (the page's button and a tap on the tile) launches `terminal` with firstmate's `<[firstmate] home>/data/tools/usage-view.py` when that file exists, else `<command> --full` (`UsageWatch.view_argv`, `desktop.launch`), the one thing it does. The app gives at most `MAX_PAGES` (4) pages: with firstmate the Agents page is given only with `[herdr] agents_page` (`Fleet.agents_page`; without firstmate always), and with it and Runs, Projects and Limits all on, the `calls` page is left out (`Fleet.calls_page`, logged once). Tests' `config()` turns `agents_page` on; pass `agents_page=False` for the default. Logos are `claude.svg` and `openai.svg` (`common.PROVIDER_ICONS`), a generic provider has the gauge. `UsageWatch(run=, launcher=, home=)` are the test seams.
- **Captain's Call is a page, and answers nothing but a change ready for review** (`callpage.py`): the app gives the apps page its `calls` page (opened by a `page = "calls"` item on the bar: the protocol has no message for an app to turn the apps page, so a tile cannot open it), and the Captain's Call widget shows the same view in place of the grid with Back (`Fleet.calls_open`); a `calls` tile tap opens the board straight away. A grid of `COLUMNS` by `ROWS` in large spans: the count, the board's button, and the calls firstmate's reader lists (`Bearings.waiting`: a decision's id and summary, a contribution's task, kind and reason), `MAX_SHOWN` then how many more. Every label and text is fitted with `fit()` to its box (`LABEL_CHARS`, `TEXT_CHARS`, `WIDE_TEXT_CHARS`, `MAX_LABEL`, from the extension's widget sizes at a 208 px bar; the module's docstring says how), errors logged whole. The button's id is `BOARD` + its state (`callpage.Board`, kept by `boardrequest.py`), and `action()` answers only for the button shown now. Nothing is asked in the bar.
- **A change ready for review has three buttons** (`reviewcall.py`, `reviewrequest.py`): a decision keyed `code-review` whose `id` (never its key) is a task id (`Call.review`, the head from `ready for review at <head>` in its summary); the first one takes both rows and the other calls are only counted. A pull request waiting for the captain (a captain contribution of kind `pr`: a task id, a commit `head`, a URL `common.pr_url` accepts) is a change ready for review too (`Call.review`, `Review.pr`; `firstmate._join_pull_requests` joins it with the task's decision at the same head into one change, Approve's note then names the pull request and merges nothing); a round is `reviewcall.key`, the task and the first 7 characters of the head, so Captain's Call, a run's card and a restart share one verdict and one request id. Review and Request changes run `[firstmate] review_command` (a program with `{task}`, strict config; unset: both hidden, Approve alone) through `Firstmate.open_review` -> `desktop.launch`: detached in a `systemd-run` scope like the browser, stdin and stdout to `/dev/null`, never waited for past `LAUNCH_GRACE`; never a hard-coded path (the repo is public). Approve and Request changes send one `fm-inbox.sh note --json --request-id <id>` (`Firstmate.review_note`, the texts in `firstmate.py`); the id is `reviewcall.request_id` (task, head and verdict), so a second press or a restart replays and wakes nothing, and once a verdict was sent or is sending no other note is offered (`Entry.locked`). A round of review is (task, head): a call naming no head gets Review only, no verdict (`review_note` refuses it too), and without `review_command` it is a plain call (`reviewcall.first`). Approve merges nothing. Whether firstmate handled it is read with `fm-inbox.sh receipts` right after the app's own firstmate reads (`Reviews.bearings`), never polled. Focusing an agent's pane (`App._focus_pane`: a card's Focus, the Runs page) whose agent is `idle` or `done`, whose task has such a decision, or whose run on the Runs page is a ready pull request (`Runs.pane_review`), and with `review_command` set runs the review (`Reviews.ready`) instead of Herdr's focus; a blocked agent (the agents tile's first blocked, a card's Focus) always gets its terminal; a task with neither, or no command, keeps today's focus. Button ids carry the state and `token(review)` and are at most 32 characters (the protocol's id limit).
- **The decisions board through firstmate's own commands** (`firstmate.py`, `boardrequest.py`): its file is `FM_HOME=<home> <code>/bin/fm-bearings-board.sh path` (only `path`, never `build`: firstmate composes and arms the board), it is open when `[firstmate] lavish` (bare `lavish-axi`, its session listing) lists that file `open` (both paths resolved), and only a loopback `http` URL goes to `gio open`, run in a transient scope of its own (`desktop.open_url`, `desktop.SCOPE`, `systemd-run --user --scope --collect --quiet --`) so a browser it starts is never in the app's unit and its `MemoryMax=64M` (a browser counted there got both OOM-killed); a missing or failed `systemd-run` opens nothing (the button says why). Opening the view looks (`board_url()`, never opening); Request board looks first (`board_url()`; a board open posts as a look, ends the wait and writes no note; a failing look goes on to the note), then asks firstmate to build it: one `FM_HOME=<home> <code>/bin/fm-inbox.sh note --json --request-id <id> -- <BOARD_REQUEST>` (one wake), then none again while the app waits for the board (the button and the Captain's Call widget say it is opening at once; every `BOARD_POLL` s it checks `board_url()` and the note's `fm-inbox.sh receipts`, read-only, until the board is open, `BOARD_WAIT` passes or `BOARD_REPLY_GRACE` after firstmate's reply; the count is read again after the request and when the board is open; nothing is kept on disk, so a restart has no wait); the id is made per request and kept after a failed note (fm-inbox.sh may have saved it, exit 1 or 3), so a retry replays rather than queueing a second, and a new one is made once the id is older than `BOARD_REQUEST_HOLD` (firstmate may have handled that note, and a replay wakes nothing) or once the board was seen open; a replay whose `fm-inbox-note.v1` answer is `acknowledged` or whose `path` is in firstmate's handled inbox (it wakes nothing) is asked again at once, in the same job, under a new id. That note and the review notes below are the only things it writes into firstmate (`receipts` only reads; it never replies to or acknowledges a note); it never calls `fm-captain-hold`, and answering on the panel is not agreed. Tests use a stand-in `systemd-run`, a stand-in opener and a stand-in `fm-inbox.sh` in the fake checkout, so no unit is made, nothing opens on the screen and no firstmate home is written; a new `Firstmate` in a test that opens the board passes `scope=` a stand-in, or it would run the real `systemd-run`.
- **Icons are the app's own SVGs, by absolute path** (`common.icon(name)`, files in `icons/`, each on its navy disc so it reads on every tone; installed with the program): the page, the tiles, Captain's Call and the cards' Back, Focus and Interrupt. A bar tile with an icon shows only it, so a tile whose source cannot be read leaves its icon out and shows its words; a widget gets an icon only where its cell has room for icon, label and text (Captain's Call in a two-row grid; a card's button then has no second line, and a disabled one says why in place of its icon). A new icon needs its file, the name check in `test_agents_fleet.py` and the table in docs/agents.md (the run card's Open PR has `flag.svg`).
- **Keys reach an agent only two ways**: an answer through `screen.guarded_send`, or Interrupt. An answer is sent only if, at the moment of sending, Herdr reports the pane still blocked by the same kind of agent, with the `state_change_seq` recorded at draw, and a fresh `pane read` taken right before `send-keys` has the digest of the lines drawn (`screen.mismatch`); otherwise nothing is sent and the card is drawn again. Never guard on Herdr's pane `revision` (it does not move when a dialog changes). Interrupt through Herdr keys checks the same kind of agent is in the pane; for a firstmate task it is `fm-control.sh` only.
- **A tap names the screen it was made on**: the answer buttons' ids carry `Screen.token()` (the seq and the lines' digest), so a changed screen is new widgets the touch bar re-arms for 0.3 s; `Card.answer_for` takes only a token equal to the screen held now, and hides the buttons while an answer is pending. Keep Back, Focus and Interrupt ids stable (a widget whose id changes on every read never arms).
- **The keymap answers only what it recognises** (`keymap.py`): a harness entry offers an answer only when the drawn lines show its option, never Always without the plain yes, and never a dialog its `refuse` pattern matches (Claude Code's folder-trust, external-imports and bypass dialogs, which must never get a key). An unknown kind is read-only. A new harness or key needs a lab check of its dialog and tests in `test_agents_card.py`.
- **no-mistakes is read, never driven** (`nomistakes.py`, the Runs page, only with `[runs]`): `axi` and `axi status` in a repo directory (`cwd`), `axi status --run <id>` and `axi rounds --run <id> --step <step> --json`, and nothing else: `read_only()` refuses any other argument list before it runs (`test_only_read_only_commands_run`); never `axi run`, `respond`, `answer`, `abort`, `retry`, `rerun`, `sync`, `handoff` or `daemon`. Its one acting command is opening a run's pull request (Open PR on the card; a run's cell takes only a tap): `desktop.open_url` in the runs thread, with the URL no-mistakes printed as the run's `pr` and only when `nomistakes.pr_url` accepts it (`https://github.com/<owner>/<repo>/pull/<n>`, nothing else); never a URL built from a branch or number (`test_only_a_pull_requests_https_url_on_the_forge_is_opened`). `RunsWatch` takes `opener=` and `launcher=`, and a loop test passes stand-ins (`Rig(..., opener=..., launcher=...)`) or it would open a real browser or window. **A run's card** (`runcard.py`, bottom row: the review buttons, Watch, Open PR) gets Review, Approve and Request changes (`Runs.card_review`, `View.review`: the newest run of its branch, ended `completed`, `checks_passed` or `passed`, a GitHub pull request, a joined task; the head is the run's own) through `Reviews.act`, the same code, entries and ids as Captain's Call (the entry of every ready run's change, card open or not, is kept by `Reviews.bearings(keep=)` from `Runs.ready_reviews`); with five buttons the state widget gives way and the project moves to the first line. **Watch** runs `[runs] watch_command` (a program with `{run}`, strict config) through `desktop.launch` in the runs thread (`RunsWatch._watch`, job `launch`), detached and never waited for past `LAUNCH_GRACE`, only for an id `nomistakes.RUN_ID` accepts, hidden when unset; it reads nothing and polls nothing. **The Runs page is a grid of project cells** (`runlist.grid`: name, machine label, how many runs are active; three to a row, nine to a page with a pager past nine, always `MAX_ROWS` rows so a cell is the same size whatever the page holds (empty positions draw nothing); a machine that could not be read is a row at the top, at most `DOWN_ROWS`, the last counting the rest), and a tap opens **the project's runs** (`runlist.project_view`: Back, the title, every run of the project, the active ones first, pages of nine; `Runs.project`, `Runs.navigate`), whose cell opens the run's card; Back on the card returns to the project's runs. `Runs._projects`, `_runs` and `_turns` are rebuilt with every page built, so a tap on an id no longer drawn does nothing. A run joins its copy by the copy's current branch (`axi status` there), the copy its agent by Herdr `cwd` and its task by the worktree firstmate's reader gives (`--fields endpoints,paths`, asked only with `[runs] firstmate`); of firstmate's home only the directory names in `<home>/projects/` are read. The warning is more than one active run per agent pane, copy or branch (`Runs.views`). Its thread reads every `[runs] poll` s while a run is active, `idle` s otherwise, and not while the touch bar is disconnected; widget text holds no time that changes each read. Tests use `runs_support.py`'s fake CLI and `FakeNoMistakes`, never a real repo or no-mistakes.
- **A remote machine's runs are read over ssh, read-only, in threads of their own** (`ssh.py`, `remotewatch.py`, `[[runs.remote]]` in `config.py`; docs/runs.md "A remote machine"): `RemoteNoMistakes` runs the same four `read_only` shapes as `ssh <target> 'cd <dir> && no-mistakes axi …'` through `Ssh`, whose argv is fixed (`BatchMode=yes`, `ConnectTimeout`, `ControlMaster` in `ssh_control_path`, `--` before the target, no `FM_*` in the environment), and only two more things run there: `find -L <home>/projects …` and firstmate's reader (`FM_HOME=<home> <code>/bin/fm-bearings-snapshot.sh --json --fields endpoints,paths`, at most each `FIRSTMATE_POLL`). ssh's exit 255 or a timeout is `Unreachable`, which `runscan.read` re-raises at the first call (never one timeout per directory) and the page shows as the first row `<name> unreachable` with the machine's runs dropped (`Runs.set_remote`, `down`, `runs.down_notice`); any other failure of the read (the machine answered, no-mistakes failed there) is `<name>: no-mistakes unavailable` the same way, never `unreachable`; this machine is always labelled `laptop` (`runs.LOCAL`, no config key); a remote's thread polls at `[runs] poll`/`idle` and not while the bar is disconnected, and never runs on the local Runs thread. Remote projects are keyed `machine:repo` (`Project.key`), a remote copy joins its own task (`Copy.task`) and none of this machine's agents or review (`View.review` is None for a remote). Watch for a remote run is `RemoteWatch.watch_argv`: the configured `terminal` here (only `{command}` is replaced) running `ssh -t` and, there, the `watch_script`'s source sent as an argument to `python3 -I -c` (nothing is installed there); a viewer that cannot be read is `DesktopError` on the card. Tests fake ssh with `runs_support.FakeSsh` through the `run` seam (`App(ssh_run=)`, `Ssh(run=)`): no test reaches a real machine.
- **Slow calls stay off the loop**: Herdr, firstmate's reader and firstmate's control (interrupts, opening the board and asking for one) and no-mistakes (`runwatch.py`) each run in their own thread (`app.py`) and hand results through a queue and a wake pipe, so a touch is handled at once. A worker never dies on an error: any exception from a read is shown and logged like the source's own errors, and one from a focus is logged, one from an answer or an interrupt is shown on the card (`test_an_unexpected_error_keeps_both_threads_going`, `test_a_refused_focus_is_logged_and_the_loop_goes_on`, `test_a_failed_send_is_shown_and_the_card_stays`). A widget's id is derived from its pane (`fleet.widget_id`), and `Fleet.pane_of` answers only for the page last built, so a tap means the agent that was drawn.
- Keep widget text free of anything that changes on every read (times, counters): a widget that changes re-arms for 0.3 s and cancels a finger on it.
